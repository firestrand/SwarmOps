# Optimization review

## Result
Reuse the running prefix sum in Schwefel 1-2, reducing additions from O(n²) to O(n).

Decision: retain with the reviewed maintainability refactors.
Modernization commit `6639fb7eaa5a4d5e937d0a38d969d063e6809dc1` is pushed to `origin/master`; the remote hash was verified. The optimization is included with the subsequent reviewed maintainability changes. Temporary measurement output is excluded from commits.

## Ablation method
Baseline `6639fb7` is extracted from Git into a temporary directory and compiled with an independent assembly name. The runner compares that implementation with the candidate in the same process. Only one optimization is enabled per repository. No combined improvements mask an individual contribution.
Run `python3 verification/run-ablation.py` from this repository. Requires Git, Python 3.12+, and .NET SDK 10.0.401.
Every case has 10,000 warmup calls and nine alternating baseline/candidate batches. Each result records its batch size and all raw timings in the ignored `verification/results.json` generated by the runner. Trials were run sequentially across repositories with `DOTNET_TieredCompilation=0` to avoid tier-transition and inter-study interference.
Runtime: .NET 10.0.12; architecture: Arm64. Medians measure the fitness/helper call workload, including identical input resets where mutation requires them. These are local microbenchmark results, not whole-application speedups. No claim is made about other hardware or default tiered-runtime performance.

## Numerical evidence
156,330 bit-exact comparisons passed. Maximum observed absolute and relative difference for finite outputs: **0**, stricter than the proposed 1e-12 ceiling.
One prefix-sum optimization. Fitnesses and full PSO evaluation traces match exactly for 30 seeds, 5000 evaluations per run. Nine alternating timing trials after warmup.
Input/state checks are included where the evaluated method mutates positions; allocation changes do not alter formulas, bounds, quantization, or random draws.

## ATLAS hardness report
- Edge cases: zero vectors, bounds, and fixed-seed random inputs are included in benchmark comparisons. The offline study additionally covers halfway rounding, negative/zero/NaN quantum values, infinities, and aliasing.
- Tool/service failures: restore, build, or numerical mismatches terminate the runner unsuccessfully. Temporary baseline files are cleaned automatically.
- Concurrency: private constant tables are read-only after initialization; no shared mutable scratch buffers introduced. Fitness routines' existing global counters and optimizer concurrency behavior remain unchanged.
- Security: no credentials, network random providers, or trading integration used in studies. Baseline extraction uses Python's data filter.
- Verification: final `dotnet build -c Debug --nologo` and `dotnet build -c Release --nologo` passed. No unit-test projects existed; the new runner supplies numerical and seeded-PSO trace checks.
- `git diff --check` passed. Existing compiler warnings are described in [the modernization report](modernization-atlas.md).

## Limits and findings for review
The original study matched 150,000 seeded PSO evaluations and final solution coordinates; the maintainability review records the expanded PSO/MOL and parallel coverage. At one dimension the change is approximately neutral; the benefit scales with dimensionality. Other optimizer implementations and objective functions were not modified.
